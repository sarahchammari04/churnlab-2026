## Part A

**A1. Why do the raw CSV, a fitted model and the training code have different roles?**
The training code is the recipe: small, written by us, reviewed and versioned in Git. The raw CSV is an external input that we must never modify; we track its identity (source URL and SHA-256) rather than its bytes. A fitted model is an output generated by running the code on the data; it can be rebuilt, is often large and binary, and belongs in an artifact store with its training metadata, not in Git. Mixing them makes it impossible to tell what was written, what was received and what was produced.

**A2. Why would including `Churn` among the inputs invalidate the task?**
`Churn` is the answer we want to predict. Giving it to the model as an input is target leakage: the model would simply copy it, score perfectly in evaluation and be useless in production, where the label is unknown at prediction time.

**B2.1** In `pyproject.toml`, the Python constraint is `requires-python = ">=3.11,<3.13"`. One direct dependency is `pandas~=2.2.0`.

**B2.2** In `uv.lock`, pandas appears as a `[[package]]` entry with `name = "pandas"`, the exact resolved `version = "2.2.3"`, its source registry and the hashes of each distribution file.

**B2.3** `uv tree` shows that `python-dateutil` (and `pytz`, `tzdata`) are transitive dependencies: we never declared them, pandas requires them. `joblib`, `scipy` and `threadpoolctl` come transitively from scikit-learn.

**B2.4 Difference between `pyproject.toml`, `uv.lock` and `.venv/`:**
- `pyproject.toml` states what the project *needs*: direct dependencies as version ranges and the Python constraint. Written by hand, committed.
- `uv.lock` records what was *resolved*: the exact version and file hashes of every package, direct and transitive. Generated by uv, committed, so everyone installs the same selection.
- `.venv/` is the *installed* result on one machine. It is local, platform-specific and disposable: it is recreated from the lock and never committed.

**B3.** `numpy ~= 1.26.0` means `>=1.26.0, <1.27.0`, so 1.26.0, 1.26.1, ... 1.26.4 are all allowed. `numpy==1.26.4` allows only one version. The range is a rule; the lock file is the decision actually taken (here 1.26.4).

## Part C

**C3.1** The target `Churn` takes two discrete values (`Yes` / `No`), so we predict a class, not a continuous quantity: it is binary classification.

**C3.2** About 73.5% of customers did not churn. A model that always predicts `No` reaches about 73.5% accuracy while detecting zero churners. Accuracy alone is misleading; we will need recall, precision, F1, ROC-AUC or PR-AUC on the `Yes` class.

**C3.3** pandas infers one type per column. `TotalCharges` contains 11 values that are a single space. A space is not a number, so pandas cannot parse the whole column as float and keeps it as `object` (strings).

**C3.4** `isna()` only detects real missing values (`NaN`, `None`). A string containing a space is a valid, non-empty string for pandas, so `isna()` returns `False`. We must strip whitespace and test for the empty string, or convert with `pd.to_numeric(..., errors="coerce")` first.
